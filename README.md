## 项目背景

公益捐助长期面临"资金去向不透明、受助方身份核验难、捐赠人缺乏信任感"的问题。TraceAid 尝试用区块链记账 + 零知识证明核验的思路，给出一个产品层面的解决方案：

- 捐款进入平台账户后，按 1:1 比例铸造链上记账凭证（TAC），作为"资金上链"的可追溯锚点
- 受助方上传资助凭证（如学籍证明、收支票据）时，通过零知识证明（ZK）流程核验真实性，核验通过后哈希上链，原始隐私材料不外泄
- 平台侧引入异常检测机制，对可疑的资金流向/签核行为进行标记与复核

## 我负责的部分：B 端管理后台

本仓库中的 `admin/` 目录是我独立设计与实现的管理后台，核心模块包括：

| 模块 | 说明 |
|---|---|
| 数据看板 | 项目数、待办事项、受益学生数、本月筹款等核心指标可视化 |
| 项目管理 | 公益项目的全生命周期管理与状态追踪 |
| 多签审批工作流 | 资金支出/凭证核验的多角色签核流程设计 |
| 凭证记录与 ZK 核验 | 受助凭证上传 → 分步核验动画 → 哈希上链结果展示的完整交互流程 |
| 异常检测面板 | 资金流向/签核行为异常的标记与展开复核界面 |
| 反馈中心 | 捐赠人/受助方反馈的归集与处理 |
| 审批规则设置 | 多签阈值、核验规则等平台参数配置 |

**技术实现**：单文件 HTML + 原生 CSS/JavaScript，无框架依赖，包含约 2900 行代码，自行设计了完整的设计系统（色彩变量、图标体系、卡片/标签/弹窗等组件库）与页面状态管理逻辑（Tab 切换、分步表单、异常面板展开收起等）。

## 关于"区块链"和"ZK证明"部分的真实情况

为避免误解，这里明确说明技术边界：**本项目当前是前端产品原型（demo），管理后台中的链上铸造、ZK 证明生成/核验、AI 异常检测均为前端模拟交互效果，用于演示完整的产品流程和用户体验，并未连接真实的区块链网络、零知识证明算法库或机器学习模型。**

我负责的工作重点是**产品流程设计与前端交互实现**：把"资金上链记账""ZK 隐私核验""异常检测复核"这类复杂技术概念，转化为普通管理员能看懂、能操作的清晰交互流程（例如 ZK 核验的分步进度动画、异常面板的展开式复核设计）。

## 竞品对比分析

TraceAid 定位于"区块链公益透明化平台"，与市场主要竞品的对比：

| 维度 | Gitcoin | Giveth | 腾讯公益 | 蚂蚁链公益 | **TraceAid** |
|------|---------|--------|---------|-----------|-------------|
| 透明化程度 | ★★★ | ★★★ | ★ | ★★ | **★★★★** |
| 隐私保护 | ★ | ★★ | ★ | ★★ | **★★★★** |
| 国内可用性 | ★ | ★ | ★★★★★ | ★★★ | **★★★★★** |
| 中小机构友好 | ★★ | ★★ | ★★ | ★ | **★★★★★** |
| 产品完整度 | ★★ | ★★ | ★★★★ | ★★★ | **★★★★** |

### Gitcoin
全球最大的开源软件捐赠平台，基于以太坊。核心优势在于二次方融资（Quadratic Funding）机制。但完全面向开源项目，不支持传统公益场景，国内用户访问受限。

### Giveth
基于以太坊的去中心化慈善平台。但在国内缺乏本地化运营，不支持中文界面和人民币支付通道。

### 腾讯公益
国内市场占有率最高的公益平台，优势在于微信生态和庞大用户基础。但本质上仍是传统模式+支付接口，未使用区块链实现真正的透明化。

### 蚂蚁链公益
蚂蚁集团旗下区块链公益平台，技术实力雄厚，但定位为企业级服务，中小机构接入门槛高。

### TraceAid 差异化优势
- **双端完整产品**：B 端管理后台 + C 端用户平台，覆盖公益全流程
- **零知识证明核验**：完整产品化的 ZK 隐私核验流程
- **低成本接入**：面向中小机构的轻量级方案
- **中文原生体验**：完善的本地化设计
