# TraceAid 链善 — 用户端功能说明文档

> **说明**：本文档列出用户端（C端）HTML页面中的每项核心功能、设计原因、功能意义，以及涉及区块链技术的专项说明。

---

## 一、页面导航与基础结构

| 功能 | 功能原因 | 功能意义 |
|------|----------|----------|
| 顶部固定导航栏 | 用户需要在任意页面快速切换，导航栏固定保证始终可访问 | 提升操作效率，降低用户迷失感 |
| Logo + 品牌名 "TraceAid 链善" | 建立品牌认知，让用户第一时间记住平台名称和定位 | 强化"区块链+公益"的品牌联想 |
| 导航菜单：首页/公益项目/新闻中心/服务说明 | 按用户行为路径组织入口：浏览→了解→参与→查看记录 | 清晰的IA（信息架构）帮助用户快速定位目标 |
| 连接钱包按钮 | 区块链交互需要用户身份标识，钱包地址作为链上身份 | 用户可直接通过钱包地址参与链上交互，无需传统注册 |
| 响应式适配（手机/平板/桌面） | 用户可能从任何设备访问 | 提高可访问性和覆盖面 |

## 三、公益项目与捐款流程

| 功能 | 功能原因 | 功能意义 |
|------|----------|----------|
| 进行中/已截止标签切换 | 区分可捐赠和已完成项目 | 用户清晰知道可参与项目 |
| 项目卡片完整信息 | 供用户决策所需的充分信息 | 降低信息不对称 |
| 项目详情弹窗（资金流向/链上信息） | 展示比卡片更多信息但不跳转 | 满足深入了解需求 |
| 金额快捷选择+自定义输入 | 减少输入成本，满足不同能力 | 提高捐赠完成率 |
| 留言功能 | 捐赠者希望表达心意 | 增加情感连接 |
| 上链确认步骤 | 执行前让用户再次确认 | 减少误操作，强调上链严肃性 |
| 捐款成功页（TxHash/区块高度） | 完整完成确认和交易凭证 | 用户可自行验证 |

### 区块链专项

| 功能 | 区块链技术 | 使用原因 |
|------|------------|----------|
| 链上资金流向模块 | 智能合约 + 链上交易记录 | 展示资金从募资到拨款的完整区块链链路 |
| 项目关联链上交易哈希 | 区块链哈希标识 | 供用户到区块链浏览器验证 |
| 第N批拨款标识 | 智能合约分批次拨款 | 资金按里程碑自动释放，防止挪用 |
| 捐款通过智能合约上链 | 智能合约 | 每笔捐款自动生成不可篡改的链上记录 |
| 唯一交易哈希(TxHash) | 区块链交易哈希 | 用户可在区块链浏览器公开查询 |
| 区块高度显示 | 区块链区块记录 | 交易精确位置标识 |
| Gas费提示 | 区块链交易Gas机制 | 展示实际上链成本，体现透明 |
| 链上状态"已确认" | 区块链交易确认机制 | 交易已被网络确认，永久有效 |

| 功能 | 功能原因 | 功能意义 |

| 用户信息+实名标识 | 公益场景需要身份真实性 | 防止虚假捐赠/求助 |

### 区块链专项

| 功能 | 区块链技术 | 使用原因 |
|------|------------|----------|
| 链上交易数统计 | 区块链交易计数 | 真正链上行为统计 |
| NFT证书 | ERC-721标准 | 不可篡改的哈希/时间戳/金额 |
| NFT证书链上铸造 | ERC-721 | 唯一性+不可篡改性 |
| 证书不可交易 | 智能合约限制交易 | 仅作为公益记录 |
| 证书永久有效 | 区块链数据持久性 | 不可删除不可篡改 |

## 七、整体区块链技术架构

| 技术组件 | 角色 | 解决痛点 |
|----------|------|----------|
| 智能合约 | 捐款上链、自动拨款、异常暂停 | 防止资金挪用 |
| 区块链存证 | 项目/捐款/拨款/证书上链存证 | 不可篡改、可公开验证 |
| 区块哈希(TxHash) | 每笔操作的唯一链上标识 | 精确追溯 |
| NFT(ERC-721) | 捐赠证书链上铸造 | 唯一、不可篡改、永久有效 |
| 零知识证明(ZKP) | 验证身份不泄露隐私 | 真实性vs隐私的矛盾 |
| 钱包地址 | 用户链上身份标识 | 去中心化身份 |
